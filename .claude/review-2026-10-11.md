# Lumen full review — 2026-10-11

Seven reviewers, one per area: router/daemon core, LLM layer, mail, calendar/todos/Today,
Canvas, UI shell + daemon seam, and Ask/Settings/Books/Files. All read-only. Their test
scripts ran against temp databases and fake services, never your data, the running daemon,
Google, or Canvas. Nothing in the code was changed. Suite at review time: **2046 passed /
19 skipped**. None of the findings below is covered by an existing test.

Evidence tags:
- **[checked]** I re-read the code path myself and confirmed it.
- **[probe]** a reviewer reproduced it with a throwaway script.
- **[traced]** read through end-to-end, not reproduced.
- **[needs you]** depends on your machine or accounts.

Where two or three reviewers found the same thing independently, it's marked ×2 / ×3.

## Tier 1 — fix first

Each of these shows wrong information every day, breaks a safety rule (no write without a
click), loses something you typed, or makes a feature not work at all.

### Dates and times (one root cause: UTC vs local)

1. **Evening events land on the wrong day.** The calendar cache buckets events by their *UTC*
   date. Anything after 6 PM (5 PM after Nov 1) is filed under tomorrow. It goes missing from
   Today, the day view, the briefing, and free-slot answers, and shows up on the next day
   instead. Canvas due-date events at 11:59 PM never appear on their own day. Tests only use
   morning times, which is why this slipped through.
   `daemon/connectors/gcal.py:41,54` (`date(start_at)` in SQLite converts to UTC). Fix: store
   a local-date column at `_normalize` time and filter on it. [checked]

2. **Event times break across daylight saving (DST ends Nov 1).** Several places take today's
   fixed −06:00 offset and apply it to future dates. After Nov 1 the bugs are:
   - A "Dentist Nov 5 2pm" is booked at 1 PM, though the confirm still says 2 PM.
   - November events show an hour off in Calendar.
   - Editing only the end time shifts the start.
   - Free slots are offered over real events.
   - A model time ending in "Z" is shown as local in the confirm but booked as UTC.

   `ui_v2/state.py:1249`, `daemon/llm/event_create.py:52-57`,
   `daemon/connectors/free_slots.py:92-99`, `daemon/router.py:666-669`,
   `daemon/llm/meeting_prep.py:61,98`. Fix: convert per instant with `.astimezone()` or
   `ZoneInfo`, as `gcal_time.tz_offset` already does. [checked state.py; probe]

3. **Canvas tab is a day off for evening deadlines.** Homework due tonight at 11:59 PM shows
   "Due tomorrow", and last night's shows "Due today" under "Next 7 days" instead of Overdue.
   The Todos screen has the right date, so the two disagree. The Ask bar context also sends the
   UTC time unlabelled. `ui_v4/screens/canvas.py:115-175` (`due_at[:10]`), same in ui_v3.
   Fix: use `canvas_events.due_local()`. [checked]

4. **Mail times reach the model in UTC, labelled as local.** A 9 PM email reads as "03:15
   tomorrow" in the briefing. The commitment scan is told an evening email was "sent on
   Friday" when it was Thursday, so "I'll send it tomorrow" lands a day late. The same happens
   in triage and meeting prep. Meanwhile `search_email` shows the correct local time, so the
   model sees two different times for the same email. `daemon/router.py:707`,
   `llm/briefing.py:76`, `llm/commitments.py:80`, `llm/triage.py:36,133,178`,
   `llm/meeting_prep.py:136,229`. Fix: `.astimezone()` before formatting. [probe ×3]

5. **Ordinary questions get no current date.** For "did Chris email me yesterday?" or "how many
   days until Christmas?" the prompt contains no date at all. Claude mode loses the CLI's own
   date line too, because `--system-prompt-file` replaces it. `router.py:436`, `:947-1004`.
   Fix: add "Today is <date> (<weekday>) <time>" after the identity/memory block, so the warm
   prefix cache still holds. [probe]

### Safety rules (writes without a click, or the wrong thing deleted)

6. **The model can run tools it was never offered.** In Local mode the tool executor runs any
   tool name the model emits. That includes `create_event`, `update_event` and
   `delete_event`, which are kept out of the offered list on purpose. A slip by the 4B
   model would write to Google Calendar with no confirm. Claude mode is safe because its schema
   limits the names. `router.py:3490-3534`. Fix: reject any name not offered this turn.
   [checked; whether the 4B would actually do it is untested]

7. **Mail rules match keywords inside other words.** The rule author is also told to emit
   "generous" keyword lists. The prompt's own BSA example matched three unrelated messages,
   which would be moved out of the inbox in Gmail on every sync:
   - a Wells Fargo statement ("bsa" inside a URL)
   - a LinkedIn "Absa Group" email
   - Mom's "troopers closed I-15"

   `daemon/connectors/mail_rules.py:31-40`, `llm/rule_author.py:17-24`. Fix: word-boundary
   matching, ignore URLs, and show sample matches in the rule confirm. [checked]

8. **"don't forget" deletes memories.** "add a todo: don't forget to call mom" goes to the
   memory-forget route, which runs before todo-add. It deletes every memory bullet and log row
   about "mom", asks for no confirmation, and adds no todo. `router.py:381-383`, `:2307`.
   Fix: require an explicit memory target ("forget what you know about…"), exclude
   "don't/not forget", and check todo-add first. [checked order; probe]

9. **A confirm that pops up while you type can be approved by Space.** Non-destructive
   confirms put focus on the Approve button: Create event, Allow file write, Save rule,
   Add to calendar. If one arrives while you're typing in the Ask bar, the next Space
   approves it. The same happens if the window was hidden and gets re-shown.
   `ui_v4/overlays.py:253-255`. Fix: focus the card itself and ignore clicks for ~500 ms
   after it opens. [checked; probe]

10. **`lumen --quit` can kill unrelated programs.** Any process whose first argument starts
    with "lumen" counts as Lumen. `nvim lumen-notes.md`, `less lumen.log` and
    `grep lumen file` would get SIGTERM and then SIGKILL, so an editor with unsaved work could
    lose it. `instance_lock.py:54-62`. Fix: match only the real console scripts or
    `-m lumen.*`. [checked]

11. **Gmail "Disabled" doesn't stop Gmail sync.** `mail.refresh` still syncs and runs your mail
    rules, which write to Gmail, on launch, on each Mail visit, and on ↻. `calendar.refresh`
    has the guard and a comment about this exact bug. `router.py:1892-1898`. [checked]

12. **Canvas "Pause sync" only pauses the timer.** Opening the Canvas tab (mirror older than
    5 minutes), Sync now, and the sign-in hand-off all still sync, including calendar writes
    and model calls. Settings says "Paused" while the tab says "Synced just now". Pausing
    Google Calendar doesn't stop Canvas→Calendar writes either.
    `connectors/canvas_sync.py:127,206,239`, `router.py:879,1307,1576-1594`. [probe]

13. **Mail keyword pre-sort treats gmail.com as one sender.** If your BSA leaders write from
    Gmail, then Mom's and recruiters' Gmail mail gets suggested as BSA, and "Accept all"
    files it away. `llm/label_keywords.py:56-61,129-135`. Fix: ignore free-mail domains.
    [probe]

14. **Any error in a UI click handler crashes all of Lumen.** PyQt 6.11 aborts the process on
    an unhandled exception in a slot, and in `lumen` mode the daemon dies with it. No
    `sys.excepthook` is installed, and when launched by Super+L stderr goes nowhere. So any
    latent screen bug is a full crash with no log. `ui_v4/app.py`. Fix: an excepthook that
    logs to `~/.local/state/lumen/ui.log` and shows a toast. [checked; probe]

### Losing what you typed or saved

15. **Files: Save can overwrite newer content on disk.** An open file is never re-read. If the
    Ask bar's file tool edits it, or the distiller rewrites memory.md while it's open, the
    editor keeps the old text, and Save (even with no changes) writes the old text back.
    `ui_v4/screens/files.py:224-232,304-305,654-666`. Fix: remember the file's modified time
    at open, reload if unchanged locally, ask "reload or keep mine" if not, and check again on
    Save. [checked; probe]

16. **Files: "Suggest an edit" is applied blind.** No diff is shown (v2 had one, and
    file-workbench.md calls the diff "the confirmation"). Apply replaces the whole buffer,
    wipes anything typed while the model was drafting, and clears undo. Two related bugs:
    - A truncated model reply becomes a truncated file on the next Save.
    - A file that starts with a code block gets cut down to the block's contents by the
      fence-unwrapping step.

    `files.py:608-626,739-750`, `llm/file_edit.py:50-52,71`, `llm/file_write.py:130-132`.
    [checked; probe]

17. **Files: unsaved edits and "kept drafts" vanish on quit.** The close button quits the app
    in `lumen` mode, and nothing checks for unsaved work, despite the toast promising "They're
    back when you open it again". `ui_v4/main.py:691-695`. Fix: Save / Discard / Cancel on
    quit, or persist drafts. [checked]

18. **memory.md loses whole sections past 4000 characters.** `load()` truncates at the cap,
    and every distill or forget run writes the truncated text back. A test with a 5,369-char
    file lost a whole section plus some bullets. Hand edits beyond the cut are lost too.
    `llm/memory.py:28-34`, `daemon/memory_worker.py:89-109`, `router.py:2466-2500`. [checked;
    probe]

19. **A failed send throws the draft away.** This happens for a bad address (`Chris
    <c@x.com>`, `a@x.com; b@y.com`, a typo) or when Gmail is unreachable. The daemon answers
    `{ok: false}`, which v4 only toasts, and the compose window is already closed. The existing
    test covers only the connection-drop path. `ui_v4/overlays.py:426-449`. Fix: reopen the
    draft when `ok` is false, and accept "Name <addr>" plus `,`/`;` lists. [checked]

20. **Canvas undoes your own changes to Canvas todos on every sync.** Move a homework's due
    date earlier and the next sync puts it back. Un-tick one (resubmission needed) and it gets
    re-ticked. "Sync now" always reports "N todos ticked off" because it re-applies every
    time. `connectors/canvas_reconcile.py:46-54`. Fix: only push when Canvas's own value
    changed (store the last-applied value). [probe ×2]

21. **Canvas creates duplicate Google Calendar events.**
    - Any failed update (Google 503, expired token) is treated as "you deleted the event", so
      the next sync creates a second one. The orphan keeps the old date forever.
    - Pressing "Keep" in the Review queue unlinks the event, so the next sync duplicates it.
    - Stale queued removals are never dropped when an item comes back.

    `connectors/canvas_calendar.py:77-90`, `connectors/gcal.py:322-338`,
    `connectors/canvas_queue.py:63`. Fix: demote only on 404/410, and mark "kept" instead of
    unlinking. [checked; probe]

### Features that don't work at all

22. **"Ask Lumen to revise" in compose always says "Revision failed."** The daemon returns
    `{subject, body}` with no `ok`, and v4 checks `ok`. `router.py:2078-2087` vs
    `ui_v4/overlays.py:466`. One-line fix. [checked]

23. **A compose window opened from chat holds the daemon's exclusive lock for up to 30 minutes.**
    While it's open, these all queue silently: Revise, another question, the briefing,
    archive/delete, and calendar writes. Then they fire late, e.g. a stale "Archive email?"
    confirm pops up after you close the draft. The same happens for 120 s whenever a chat is
    waiting on any confirm. `daemon/ipc_server.py:79-81`, `router.py:757-782,3212`. Fix: hold
    the model lock only around generation, and use a separate one-dialog-at-a-time lock.
    [checked ×2]

24. **The rule checkbox "Also label the N matching emails" never appears.** The daemon sends
    `check: {label, checked}` and v3/v4 read `check_label`. The backfill never runs; this is
    the "emails didn't get the new label" half of #36. `ui_v4/overlays.py:237-240` (and
    ui_v3/overlays.py:136) vs `router.py:3379-3392`. [checked ×3]

25. **When the tool loop hits its step limit, the recovered answer is thrown away.** The #45
    salvage answer arrives flagged `capped`, and the router replaces it with "(stopped after
    several tool steps…)". In Local mode that wastes a full generation. `router.py:3561-3562`;
    `test_chat_capped_yields_stopped_message` pins the old behaviour. [checked]

26. **Turning the model Off doesn't stop work already queued or running.** A distill scheduled
    2 minutes after your last chat still runs. Canvas enrichment, a running suggest-labels
    batch and an in-progress answer keep calling Ollama after the unload. That reloads the 4B
    for 10 minutes right after you said Off. `llm/backend.py:180-182` (Off still routes to
    Ollama), `memory_worker.py:65-69` (no re-check after the delay), `router.py:1135-1148`.
    Fix: `LLMBackend` refuses calls when Off, and the worker re-checks after its sleep.
    [checked ×3]

27. **The Todos quick-add hint teaches a format the parser doesn't accept.** The hint says
    "a weekday like 'friday' gives it a due date" and the placeholder is "Renew the domain
    friday #admin". The parser only understands `@friday`. So the date stays in the text with
    no due date, and the todo never shows in "Due today". The same goes for
    "remind me to pay rent friday" in chat. `ui_v4/screens/todos.py:533-542`,
    `connectors/todo_parse.py:246-263`. Fix: resolve plain date phrases on capture (or at
    least fix the hint). [checked]

28. **The New-event form ignores the daemon's reply and loses your input on error.** There's no
    toast for success or for "Couldn't reach Google Calendar". Today never shows the new
    event. The form closes before validation, so "9:30", "2pm" or a blank End is rejected
    after everything you typed is gone. The edit dialog accepts 9:30; create doesn't, and has
    no all-day option. `ui_v4/overlays.py:542-559`, `today.py:447-449`,
    `calendar.py:765-773`. [probe]

## Needs your decision — friction and product calls

These change how something works or looks for you, so they're your call. Each has a suggested
default.

1. **Canvas tab ordering.** All past work, including graded and submitted items, sits in an
   "Overdue" section at the top, oldest first. With 30 graded homeworks, Friday's project is
   row 35. *Suggest:* a collapsed "Done" section, Overdue only for unsubmitted work, and
   upcoming first.
2. **Canvas when the session expires in the background.** The tab replaces your
   assignments/announcements with the first-run "Bring your coursework into Lumen" card, and
   nothing elsewhere says you were signed out. *Suggest:* keep the lists, plus a "Signed out
   of Canvas — Sign in" strip.
3. **Canvas at term end.** Every event from ended courses is queued for removal, labelled "Its
   course is turned off", and you can only Keep them one by one. *Suggest:* don't remove past
   events at all, or add "Keep all".
4. **Canvas announcements in the briefing.** It shows the 5 newest every day regardless of age,
   including ended courses. *Suggest:* only unseen ones from the last few days. Also add a
   "due tomorrow" line and cap the overdue list at "5 + N more".
5. **A Stop button for answers in progress.** Right now a slow answer locks both Ask surfaces
   and everything queued behind it.
6. **Model Off blocks things that don't need the model.** "add a todo: X", "mark X done" and
   the free-slot finder are refused while Off. *Suggest:* let those through.
7. **Today screen.** Should clicking a todo there open its detail directly? It currently jumps
   to the Todos screen and you have to find it.
8. **Todo order.** Lists are in creation order; todo-system.md says by due date. *Suggest:* sort
   by due date within each group, overdue first. (Separate from the deferred #71 redesign.)
9. **Mail completeness.** Each of these is a small feature:
   - a Cc field
   - Reply-all
   - honour Reply-To (no-reply senders)
   - "Show more" past 50 per mailbox
   - Mail re-reads new mail while you sit on it (email-menu.md promises a 5-minute re-read; v4
     has none)
   - inline `cid:` images
   - an "Open in Gmail" link for attachments
10. **Undo for deletes.** Conversations and mail rules delete instantly with no Undo, unlike
    todos. Books have no delete or edit at all. Enter in Title adds a book with no author and
    a default 5 stars, and a suggestion's "Add to log" logs it as a finished 5-star read.
11. **Files opens by extension, not content.** README, Makefile, .bashrc, .gitignore, .csv, .c/.h
    and .gd/.tscn are greyed out as "not text". *Suggest:* decide by content (the reader
    already detects binary and non-UTF-8 files).
12. **Calendar.** Should the edit dialog show/clear location and edit the description? Should
    there be keys for prev/next/today/new? Should events beyond the sync window be fetched on
    demand, or just labelled "Lumen keeps 30 days back to 60 ahead"?
13. **Claude-mode wording.** Should Files and Settings say plainly what is sent to Claude when
    Claude mode is on? (Item 88 above is the factual error; this is about how much to say.)
14. **Follow-ups after "Continue in Ask Lumen"** lose the page context (the file, the open
    email), so "expand step 2" or "label it" can't resolve. *Suggest:* carry the context
    with the seeded conversation.
15. **Ask history.** Only the newest 50 conversations are reachable. Add paging?
